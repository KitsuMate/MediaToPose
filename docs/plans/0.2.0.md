# Media to Pose 0.2.0 plan: clean core, agentic and CLI use

## Goal

0.2.0 makes the code base easier to maintain and lets an agent or a script
create and refine animations without the Blender UI:

1. Clean structure: clear layers, smaller modules, one shared model backend,
   typed errors, no pickle, fast tests that do not need Blender.
2. Agentic and CLI use: a synchronous Python API, a `blender -c` command,
   machine-readable results, quality metrics and comparison renders.

User-visible behaviour of the existing panels must not change, except where a
phase below says so.

## Ground rules

- **All work happens on the branch `feature/0.2-clean-core-agentic-cli`.**
  Never commit to `main`. Create the branch from `main` if it does not exist:
  `git switch -c feature/0.2-clean-core-agentic-cli main`.
- Keep the branch up to date by merging `main` into it, not by rebasing
  published commits.
- Commits use the existing conventional style (`refactor:`, `feat:`, `test:`,
  `ci:`, `docs:`, `build:`). Moves and renames get their own commits with no
  behaviour change, so `git log --follow` and review stay usable.
- Every commit must pass `ruff check`, `ruff format --check`, the unit test
  tier (once it exists) and the Blender suite.
- Commits may be created locally at any time. **Pushing and opening the PR
  need explicit approval from the maintainer** (see Phase 9).
- Commit messages and the PR description contain no Claude or AI attribution
  lines (no `Co-Authored-By: Claude`, no "Generated with Claude Code").
- Files in `.workspace/` and untracked media in `docs/media/` are not part of
  this work and must not be committed.

## Conventions (written into `AGENTS.md` in Phase 1)

### Layers

Allowed import direction:

```
blender → api → session → retarget, postprocess, rig, providers, backends → core
```

- `core/` imports only the standard library and numpy. No `bpy`, no
  `mathutils`.
- `mathutils` is allowed in `rig/` and `retarget/`.
- Nothing imports `blender/` except the package `__init__.py`.
- Enforced by `tests/unit/test_layering.py`, which parses every module's AST.
  It starts with an allowlist of current violations; each phase removes
  entries, and the list must be empty before release.

### Blender access

- Only `blender/operators/*` and `api/` read `bpy.context`. Everything else
  takes scene, armature and fps as arguments.
- Blender data is changed only on the main thread. Worker threads see only
  `core` types.
- PropertyGroups are converted to frozen dataclasses once, at the operator or
  API boundary. Lower code never does `getattr(settings, "x", default)` on RNA.

### Long-running work

- `iter_x(...)` yields `Progress`. A plain `x(...)` drains it.
- A `CaptureSession` exposes `step()` and `cancel()`. The modal operator, the
  synchronous API and the CLI are all just drivers of `step()`.

### Errors and logging

- All raised errors subclass `core.errors.MtpError` (`MediaError`,
  `ModelMissing`, `MappingIncomplete`, `OperationBusy`, `Cancelled`,
  `BackendError`). Each has a stable `code` string.
- `except Exception` is allowed only at thread entry points, operators and
  the CLI entry, and must log the traceback. Ruff `BLE` enforces this.
- Use `logging.getLogger(__name__)` under one `media_to_pose` logger. No
  `print` outside `ci/`.

### Data and files

- No pickle. Intermediate and cached data use npz (`allow_pickle=False`) plus
  JSON manifests with `schema_version`.
- Atomic JSON/npz writes live in `core/fs.py` only.
- `pathlib.Path` for all paths.

### Python style

- Ruff adds `UP`, `RET`, `PIE`, `PTH`, `BLE`, `TID252` to the current rules.
- Built-in generics (`list[int]`), `X | None` instead of `Optional[X]`.
- Frozen dataclasses for requests, results and snapshots; `Enum` for modes and
  states instead of bare strings.
- Pyright basic mode on `core/`, `providers/`, `postprocess/`, `api/`; widen
  later.
- Soft limits: about 600 lines per module, about 80 per function. Exceptions
  are deliberate and noted in review.

### Blender naming

- `bl_idname` prefix `mtp.`; classes `MTP_OT_`, `MTP_PT_`, `MTP_UL_`,
  `MTP_MT_`; PropertyGroups `MTP<Thing>`.
- Each `blender/` module exports `CLASSES`; only those are registered.

## Phases

Each phase lists its commits roughly in order and the condition for being
done. Phases 1 to 7 are refactors; Phase 8 is the new feature surface.

### Phase 0: Branch and baseline

- Create or switch to `feature/0.2-clean-core-agentic-cli` from `main`.
- Run the full Blender suite on `main` and record runtime and results in the
  PR draft notes, so later regressions are visible.

Done when: the branch exists and the baseline is recorded.

### Phase 1: Rules and tooling (no behaviour change)

- `docs: add AGENTS.md with layout, conventions and test commands`
- `build: extend ruff rules (UP, RET, PIE, PTH, BLE, TID252)` with the
  autofixes applied in a separate `style:` commit. Use temporary per-file
  ignores for `BLE` where the review in Phase 4 is still pending.
- `build: add pyright basic config` for modules that already pass.
- `test: add AST layering test with allowlist of current violations`.

Done when: CI is green with the new rules.

### Phase 2: Safety net

- `test: add plain pytest tier under tests/unit` covering modules without
  `bpy`: `animation_cleanup`, `motion_filter`, `camera_calibration`,
  `grounded_cleanup`, `rohm_correction`, `rig_planning`, `capture_state`,
  `operation`, `media_io`.
- `test: add golden retarget snapshots` on the VRoid fixture: per-bone
  rotations and root location for one still pose and a short sequence (from
  cached detections, so no inference is needed), compared with tolerances. Add
  a `--update-golden` switch for intended changes.
- `ci: run unit tier before the Blender job`.

Done when: the unit tier runs in under 30 seconds without Blender, and golden
snapshots pass on unchanged code.

### Phase 3: Move the extension into `media_to_pose/`

- `build: move extension source into media_to_pose/` (pure `git mv`).
- `ci: build with --source-dir media_to_pose` in all four workflows and the
  `ci/` scripts; drop the now unneeded `paths_exclude_pattern` entries.
- Tests import the package as `media_to_pose`.

Done when: release packages are byte-for-byte equivalent in content (apart
from paths) to `main`, checked with `ci/validate_distributions.py`.

### Phase 4: Errors, logging, no pickle

- `refactor: add core.errors hierarchy` and raise these instead of bare
  `RuntimeError`/`ValueError` at module boundaries.
- `refactor: narrow broad exception handlers` module by module (about 55

- `refactor: add media_to_pose logger and replace print calls`.
- `refactor: replace pickle temp files with npz frame stream` in the capture
  worker and `retarget` (the three `pickle.dump`/`load` sites).
- `refactor: add core/fs.py with atomic writers` and remove the duplicates.

Done when: no `pickle` import, no `print` outside `ci/`, `BLE` clean.

### Phase 5: Shared model backend

- `refactor: add backends/lifecycle.py ModelBackend` covering pinned download

- `refactor: port AnyCalib backend to ModelBackend`.
- `refactor: port RoHM backend to ModelBackend`.
- `refactor: port SAM 3D backend download/install to ModelBackend`.
- Move each backend and its runtimes into `backends/<name>/`.

### Phase 6: Capture session out of the operator

- `refactor: split detection_cache into core/cache/`.
- `refactor: split mediapipe provider and sam3d vith runtime`.
- `refactor: split ui and properties into blender/ui and blender/properties`.
- `refactor: move remaining modules into the target layout`.

Done when: the layering allowlist is empty, no module over about 800 lines

### Phase 8: Agentic and CLI support

#### 8.1 Synchronous Python API (`media_to_pose.api`)

```python
from media_to_pose import api

result = api.capture(
    media="clip.mp4",
    armature="Rig",
    provider="MEDIAPIPE",
    parts={"body", "hands"},
    frame_range=(0, 120),        # source frames, optional
    start_frame=1,               # timeline frame
    root_motion="FROM_VIDEO",
    config=None,                 # dict from api.get_config(); None = rig's own
    output="NEW_ACTION",         # or REPLACE, NLA_STRIP
)
```

- Drives `CaptureSession.step()` until done. Works in `blender -b` and from
  the Blender MCP `execute_blender_code`.
- Raises `MtpError` subclasses with stable `code` values.
- The operator gets an `execute()` path that calls the same code.

#### 8.2 Structured results

`CaptureResult` (also written as JSON with `schema_version`):

- action, slot, frame range, frames processed
- per-frame and per-part confidence
- filled gaps and rejected detections as frame ranges
- cleanup steps run, their parameters and per-step statistics (root drift
  removed, foot-contact frames, smoothing amount)
- mapping issues and face output warnings
- warnings with codes

#### 8.3 Introspection and configuration

- `api.describe_rig(armature)`: mapping coverage per section, unmapped
  targets, detected profile, shape keys and face bones.
- `api.list_postprocessors()`: built from `settings_schema.py`.
- `api.get_config(armature)` / `api.set_config(armature, dict)`: one JSON
  config built on the existing preset export/import, validated against the
  schema.
- `api.list_providers()` / `api.model_status()`: availability, supported
  parts, download size.

#### 8.4 Refinement tools

- `api.retarget_cached(...)`: re-run retargeting and cleanup from the
  detection cache without inference.
- `frame_range` on capture and retarget for partial re-runs.
- `api.export_detections(path)` / `api.import_detections(path)`: per-frame
  landmarks in npz + JSON so an agent can inspect or edit them.
- Output modes `NEW_ACTION`, `REPLACE`, `NLA_STRIP` so versions can be
  compared.

#### 8.5 Evaluation

- `api.evaluate(armature, action) -> Metrics`: foot sliding, ground
  penetration, jitter (high-frequency energy), joint-limit and twist
  violations, root speed spikes, landmark fit error.
- `api.render_comparison(path, frames=...)`: contact sheet or short video
  with source frame, detected skeleton and posed rig side by side, for
  vision-capable agents.

#### 8.6 Command line

Register a Blender CLI command with `bpy.utils.register_cli_command`:

```
blender -b scene.blend -c media_to_pose capture --media clip.mp4 \
    --armature Rig --parts body,hands --out result.json --save
blender -b scene.blend -c media_to_pose describe-rig --armature Rig
blender -b scene.blend -c media_to_pose evaluate --armature Rig --out metrics.json
blender -b scene.blend -c media_to_pose config get|set --armature Rig [file.json]
```

- JSON on stdout when `--json` is given, exit code 0 on success and a
  non-zero code per error class.
- `--save` writes the .blend; without it nothing is saved.

#### 8.7 Documentation for agents

- `docs/agents.md`: recipes (animate a rig from a video, fix a bad section,
  tune foot contact, set up face capture), metric meanings and acceptable
  ranges, and which cleanup step to adjust for which symptom.
- README section "Scripting and command line".

Tests: unit tests for config validation, metrics and result serialisation;
Blender tests for `api.capture` in background mode, `retarget_cached`,
and each CLI command on the VRoid fixture.

Done when: an agent can, from a fresh background Blender, capture the fixture,
read the result JSON, evaluate it, change a cleanup parameter, re-run from
cache and see the metrics change, with no UI.
