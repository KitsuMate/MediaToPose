# Media to Pose 0.2.1: reliable, verified face capture and transfer

Branch: `feature/0.2.1-face-capture`, cut from `feature/0.2-clean-core-agentic-cli`
(rebase onto `main` once 0.2.0 is merged).

## Why

Face capture is marked experimental and is the least tested part of the
extension. In 0.2.0:

- No fixture contains a face (`expected_face_landmarks = 0`), so real face
  detection never runs in any test.
- There is no golden snapshot for face output; the shape-key, FACS and
  face-bone paths of `retarget/solve/face.py` are not covered end to end.
- The only test rig (VRoid) has 57 `Fcl_*` expression keys that match no
  supported scheme: `describe_rig` reports the scheme as `NONE`, and 0 of 104
  shape entries and 0 of 13 face-rig entries are mapped.
- `describe_rig` still reports `arkit`, `facs`, `shapes` and `face`
  completeness as 1.0 for that rig, because a section with nothing to map
  counts as complete when face capture is off.
- Mirrored input flips the image before detection, but nothing visible swaps
  `...Left` / `...Right` blendshapes back to the subject's sides.
- Video face values get no temporal treatment of their own: no smoothing
  tuned for expressions, no blink preservation, no neutral calibration.

Much of what "correct" means for faces is visual: whether a smile reads as a
smile on the rig, whether eyes close fully on a blink, whether the jaw and
lips agree. Numeric tests catch regressions; they cannot judge likeness. This
release therefore pairs programmatic tests with an image review protocol in
which the agent renders face comparison sheets and inspects them.

## Goals

1. Face output that is correct for the common rig types: ARKit 52 shape keys,
   FACS, VRM/VRoid expressions, and bone-driven faces (Rigify, ARP).
2. Faces in the test fixtures, with expected coefficient ranges, and golden
   snapshots for every face output path.
3. Truthful readiness: completeness, warnings and `describe_rig` say what is
   actually mapped.
4. Expression-aware video processing: blinks survive smoothing, neutral
   faces sit at rest, gaze is stable.
5. Face metrics in `evaluate` and a face close-up mode in
   `render_comparison`, so agents can judge and tune face transfer.

Out of scope: new face detectors, lip-sync from audio, and a full FACS
solver; native FACS values stay an approximation from ARKit coefficients.

## Phase 0: Face fixtures

- **Stills** (CC0 or maintainer-provided, recorded in
  `tests/fixtures/fixtures.toml` with source and licence): neutral, broad
  smile, jaw open, both eyes closed, left-only and right-only blink, brows
  raised, pucker, gaze left and right, head turned about 30°, low resolution
  (face around 80 px wide).
- **Video**: about 3 s of talking plus blinks, 24 fps, kept small.
- **ARKit test rig**: a generated head mesh with all 52 ARKit shape keys, each
  moving a distinct, labelled vertex region, built by
  `tests/fixtures/rigs/build_face_rig.py` so it is reproducible and needs no
  licence. Add a face-bone variant (jaw, eyes, brows, lip corners) for the
  bone path.
- The VRoid fixture stays as the VRM expression case.
- **Production face rig** (maintainer's offer): `Nyx.FaceFX` from the
  maintainer's character scene, a 1,479-vertex face mesh with 202 shape keys
  on an Auto-Rig Pro armature with about 175 face bones (jaw, lips, tongue,
  eyes, brows). Its keys are ARKit coefficients behind prefixes
  (`facs_bs_EyeBlinkLeft`, `facs_bs_JawOpen`), corrective keys
  (`facs_cbs_EyeFullCompressionLeft`), controls (`facs_ctrl_MouthPucker`) and
  visemes (`facs_ctrl_vAA`). Adapt it as a face-only ARP fixture: the head
  mesh, the face part of the armature and the morphs, nothing else. It is
  the realistic case for the ARP bone path and for prefixed ARKit names.
  Whether it may be committed (it would ship in the public repository) is
  the maintainer's call; otherwise it stays in `.workspace/` and is used
  only for the visual review.
- Expected values per still go in `tests/fixtures/expected/` as ranges (for
  example `jawOpen >= 0.5`, `eyeBlinkLeft >= 0.6` and `eyeBlinkRight <= 0.3`),
  not exact numbers.

The maintainer chooses or approves the face photographs; real people need a
licence that allows redistribution in the repository.

## Phase 1: Correctness fixes

- Completeness: report face sections as "not requested" (`null` in the API,
  hidden in the panel) instead of 1.0 when nothing is mapped or face capture
  is off. Fix `describe_rig` to match.
- Mirror: when `mirror_input` is set, swap `...Left` / `...Right` blendshapes
  and eye-gaze sides after detection, matching what hands already do. Add a
  test with a flipped still.
- Prefixed ARKit names: `shape_scheme` classifies `facs_bs_EyeBlinkLeft`
  as FACS because of the `facs` prefix, although the name after the prefix
  is the ARKit coefficient `eyeBlinkLeft`. Match the ARKit name first,
  ignoring known prefixes (`facs_bs_`, `bs_`, `blendShape.`), and treat
  correctives (`facs_cbs_`) and controls (`facs_ctrl_`) as not directly
  driven. Test on the Nyx key list.
- VRM / VRoid expressions: add a `VRM` face scheme that maps ARKit
  coefficients onto the VRM preset expressions (`blink`, `blink_l`,
  `blink_r`, `aa`, `ih`, `ou`, `ee`, `oh`, `joy`, `angry`, `sorrow`, `fun`,
  `surprised`, `lookUp/Down/Left/Right`) and the VRoid `Fcl_*` names. Detect
  it in `rig/face_schemes.py` and auto-map it.
- Review `facs_values` against the FACS definitions it approximates, fix the
  sources that disagree (AU25/AU26/AU27 currently all follow `jawOpen`), and
  document the approximation in the code and `docs/agents.md`.
- Eye gaze: check the sign of every axis on the generated rig and on VRoid
  (`J_Adj_*_FaceEye`), and clamp gaze to the rig's eye range.

## Phase 2: Expression-aware video processing

- A `FACE_CORRECTION` clean-up module in `postprocess/` with schema settings:
  - smoothing per expression group (brows, eyes, mouth, jaw), lighter than for
    the body;
  - blink preservation: detect blink events before smoothing and keep their
    depth and timing;
  - neutral calibration: subtract each coefficient's resting level, measured
    from the quietest frames or from a chosen neutral frame;
  - per-group gain and deadzone, so small detector noise does not twitch the
    face;
  - hold and fade out when the face is lost, instead of snapping to neutral.
- Statistics recorded in the capture report: blinks detected and kept,
  calibrated offsets, frames with no face.
- The detection filter learns face confidence, so a turned or occluded face
  lowers its weight instead of producing extreme values.

## Phase 3: Diagnostics, metrics and renders

- Capture result: per-frame face confidence already exists; add the applied
  value of each mapped expression, and which source coefficients had no
  target (`unmapped_expressions`).
- `evaluate` face metrics (with `result`):
  - `expression_fit`: mean absolute difference between detected coefficients
    and the values applied to the mapped targets, after gain and clamp;
  - `blink_recall`: share of detected blinks that reach at least 80 % closure
    on the rig;
  - `face_jitter`: high-pass energy of the applied values;
  - `asymmetry`: left/right difference where the detection was symmetric.
- `render_comparison(face=True)`: crop the source to the detected face box,
  frame a camera on the rig's head (from the head bone and face mesh bounds),
  and draw a bar chart of the top coefficients beside both, so a reviewer
  sees detection, numbers and result together.
- `describe_rig` face section: scheme per mesh, mapped and unmapped
  expressions, face bones, eye bones and their rest axes.

## Phase 4: Visual review protocol

Some outcomes can only be judged by looking. For each fixture and output
path (ARKit rig, VRoid, face bones):

1. Capture through the API and render a face comparison sheet (stills one row
   each; video every fourth frame plus every detected blink).
2. The agent inspects each sheet against a checklist and records the verdict:
   - expression category matches (smile, open jaw, closed eyes, raised
     brows, pucker);
   - left and right are not swapped, including with mirrored input;
   - blinks close the eyes fully on the rig and reopen;
   - gaze looks the same way as the source;
   - no broken geometry (overshooting keys, combined keys exceeding limits);
   - neutral source gives a neutral rig.
3. Sheets and the checklist go in `.workspace/face-review/` with a short
   `review.md` per run, summarised in the pull request. Sheets are not
   committed as goldens: render output varies across platforms and drivers,
   so numeric snapshots remain the regression guard.
4. Every visual finding becomes either a code fix with a numeric test that
   would have caught it, or a documented limitation.

## Phase 5: Tests

- Unit: `facs_values` against hand-computed cases; VRM scheme detection on
  name lists; mirror swap; face correction module (blink preservation,
  calibration, hold and fade) on synthetic coefficient series.
- Blender, synthetic: canonical frames with chosen blendshapes applied to the
  generated ARKit rig, its bone variant and VRoid, checking every mapped
  target's value. Golden snapshots `still_face_arkit.json`,
  `still_face_vrm.json` and `sequence_face_arkit.json`.
- Blender, real MediaPipe: every face still detects a face and its key
  coefficients fall in the expected ranges; the video produces the expected
  number of blinks.
- API and CLI: `capture --parts face` on the generated rig; face metrics and
  `render --face` produce output.

## Phase 6: Documentation and release

- `docs/agents.md`: a face recipe per rig type, face metrics with acceptable
  ranges, and what to change for each symptom (eyes not closing, mouth
  too weak, face twitching, sides swapped).
- README face section: supported rig types and what is still experimental.
- Version 0.2.1, CHANGELOG entry, the full check suite, PR text including the
  visual review summary. Ask before pushing and before opening the PR.

## Done when

- Every face output path has a fixture, a golden snapshot and a real-detector
  test.
- `describe_rig` and the panel report face readiness truthfully.
- The visual review of every fixture passes its checklist, with findings
  fixed or documented.
- An agent can capture a talking clip onto the VRoid rig and the ARKit rig,
  read `expression_fit` and `blink_recall`, change a face setting, re-run from
  the cache and see both the metrics and the face sheet improve.
